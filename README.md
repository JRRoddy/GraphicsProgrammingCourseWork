This project was a delve into graphics programming and many different techniques. Allowing me to push by knowledge of graphics programming and really get into the nitity gritty when it comes to the graphics pipline learning about all the stages from the vertex shader right through to tessellation  and geometry shaders.This project also gave me great insight into working with compute shaders and how they can be used to fully control the parallelism the GPU provides. Below details a few of the techniques used.

Shadow mapping:
Used to generate shadows for objects within the scene, makes use of two main transofmration matrices(projection and view) formed from the lights perspective based on things such as its position and orientation in space. These matrices are then used within a shadow pre pass that renders all objects from the lights perspective, which then forms a depth buffer that represents how close objects are to the light itself with higher depth values meaning objects are further away according to the lights perspective. This depth buffer formed from the shadow prepass can then be used to detect if an object should be in shadow when rendering it from the cameras persepctive, as we can get the depth value of the object from the main cameras perspective(using the same transformation matrices mentioned) and compare it to the depth in our depth map formed from the shadow pre pass(if the depth is greater from the cameras perspective the object is in shadow). 

Compute based terrain generation:
Using compute shaders to generate height maps to warp and manipulate terrain vertices, in this we generate noise for the height map using the work groups defined by compute shader dispatch call to allocate specifc section of pixels within the image buffer to GPU threads.Allowing us to compute noise per pixel where each pixel is operated on by a GPU thread. The generation of the height map for the terrain generation to the GPU allows for real time editing of the terrain properties such as the number of octaves for the noise, lacunarity, persistance, and amplitude.

Deferred rendering:
Deferred rendring is a technqiue that is used to prevent overdraw for light heavy scenes as it pre calculates all of the geometry data for the lighting such as normals, world space positions, and colour derrived from texture maps in what is know as a GPass which ocurrs before all of the lighting passes take place. The GPass stores this data in different GBuffers(ussually frameBuffers with texture attachments) which are then passed to subsequent lighting passes. This means that we have all of our lighting data we need pre stored and we know that all of it should be on screen as the data within the GBuffers will have be what survived things such as the depth test when we did the GPass(which discards fragments that are occluded by others coming in) allowing us to simply write to the colour produced by the lighting directly to the screen (or an of screen buffer for pos processing to be applied).Overall, This means that we wont discard fragments that are generated by the light pass meaning that no expensive lighitng work is wasted.
